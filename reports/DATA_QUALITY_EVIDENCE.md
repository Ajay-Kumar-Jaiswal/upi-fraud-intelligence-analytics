## 3. Malformed IDs — normalized
- **transactions**: user_id/merchant_id/txn_id were already in a clean, single format in this file (verified, not assumed — see DATA_AUDIT.md §3.1).
- **kyc_records**: user_id had 6 distinct raw formats (USR12345, usr12345, USR-12345, USR 12345, USR_12345, bare 12345) — all normalized to `USR#####`.
- **merchants_master**: merchant_id had the same 6-format problem — normalized to `MCH####`.
- **chargebacks**: txn_id had 3 raw formats (TXN00012345, TXN12345, txn-00012345) — normalizing raised the match rate to fact_transactions from 89.4% to 93.11%.

## 4. Malformed currency/amount fields
- transactions.amount: 0 unparseable after cleaning (out of 20,000) — 420 negative-sign values flagged (sign stripped, magnitude preserved, original preserved in `amount_raw`).
- kyc_records.monthly_income: 1778 disguised-null values ("Not Available" etc.) correctly coerced to null, not 0.
- merchants_master.declared_avg_ticket_size: 501 negative-sign values flagged.
- chargebacks.disputed_amount: 220 negative-sign values flagged.

## 5. Timestamp normalization
- transactions.timestamp: 990 raw Unix-epoch values detected and converted; 0 unparseable after cleaning.
- kyc_records.date_of_birth: epoch detection was extended to include **negative** epoch values (pre-1970 birth dates) after initial testing found 755 false "invalid" flags — see DATA_AUDIT.md changelog. After the fix: 3 genuinely unparseable.

## 6. Status / categorical normalization
- transactions.status: 0 unrecognized values after mapping 14 raw spellings to 4 controlled values.
- kyc_records.kyc_status: 16 raw spellings mapped to 4 controlled values.
- merchants_master.merchant_category: **82 raw labels → 12 canonical categories**, 0 unmapped after the evidence-based remap (an earlier draft mapping, built without checking the full value_counts() output, left 3,731 values unmapped — caught in testing and rebuilt from the complete real value list).
- chargebacks.severity: 0 unrecognized after collapsing 3 concurrent coding schemes (word/letter/P-code) into 4 controlled values (P-code mapping is a documented ASSUMPTION, not a data fact — see src/config.SEVERITY_MAP).
- chargebacks.reason_code: 34 raw labels → 6 canonical reasons.

## 7. Missing UTR / MCC
- UTR missing: 1000 transactions (5.0%) — never reconstructed.
- MCC missing: 2872 transactions (14.4%).

## 8. KYC / merchant identity-collision evidence
- 13,316 of 36,122 cleaned KYC rows share a normalized user_id with at least one other row that has a DIFFERENT name/PAN.
- 3,262 of 6,198 cleaned merchant rows share a normalized merchant_id with a different merchant_name.
- This is preserved as a flag column (`user_id_has_identity_collision`, `merchant_id_has_identity_collision`), not resolved by silent deduplication.

## 11. Reproducibility evidence
This report and every number in it is regenerated by re-running, in order:
```
python scripts/run_pipeline.py                 # RAW -> cleaned Parquet + cleaning_report*.csv + data_quality_after.csv
python scripts/generate_analytics_reports.py    # -> join_coverage_report.csv + analytics_validation.md
python scripts/generate_data_quality_evidence.py  # -> this file
```
The full test suite (`pytest tests/`) re-validates every cleaning rule and several of the numbers above as regression guards (e.g. `test_kyc_identity_collision_flag_present`, `test_merchant_category_performance_no_categories_invented`, `test_relationship_match_rate_matches_audit_finding`).
